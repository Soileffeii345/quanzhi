# 技术与数据方案

## 1. 样品技术原则

- 先验证产品交互，再投入真实数据接入。
- 页面与数据层分开，未来可替换数据来源。
- 演示数据具有来源状态字段，避免与真实数据混淆。
- 首版优先保持简单、稳定、易演示。

## 2. 建议结构

- 前端：响应式网页，负责搜索、筛选、展示和收藏交互。
- 搜索层：统一处理币名、别名、关键词和评级盒编号。
- 数据层：钱币主数据、成交记录、在售记录、平台信息。
- 后续任务层：按天更新允许接入的数据源。

## 3. 核心数据对象

### 钱币品种

名称、别名、类别、国家、年份、材质、重量、面值、版别及图片。

### 单枚评级币

评级机构、评级分数、盒编号、对应币种及可确认的流转记录。

### 市场记录

平台、类型（成交/在售/拍卖）、标题、价格、币种、时间、图片、原链接、价格口径、匹配置信度和数据状态。

## 4. 搜索方案（样品）

1. 清理空格、大小写和常见符号。
2. 判断是否像评级盒编号。
3. 编号模式走精确匹配；名称模式拆分关键词。
4. 在正式名称、别名和特征字段中匹配。
5. 按完整命中、关键词命中数量及品种热度排序。
6. 宽泛结果先展示候选币种。

## 4.1 图片搜索流程

1. 用户上传评级盒正面照片。
2. 浏览器本机 OCR 提取标签文字，不主动上传到第三方业务服务器。
3. 从文字中解析评级机构、盒号、评级、年份和币名候选。
4. 用户人工核对识别结果。
5. 只有用户确认后才把盒号带入精确搜索。
6. OCR 置信度不足时引导重新拍摄或手动输入，不输出真假鉴定结论。

## 5. 数据状态

每条记录必须属于以下状态之一：

- `demo`：为产品演示人工构造。
- `public_verified`：来自可公开访问且已核对的来源。
- `partner`：未来通过平台合作取得。
- `unverified`：尚未核实，只可显示为可能相关，不进入行情统计。

## 6. 平台接入评估标准

- 是否公开可访问。
- 是否允许展示及链接回原页面。
- 是否需要账号、验证码或小程序环境。
- 页面字段是否稳定。
- 成交记录下架后是否仍可访问。
- 更新一次的时间与成本。
- 是否存在服务条款、版权、隐私或反自动化风险。

## 7. 风险与应对

- 数据无法获取：样品阶段使用明确标注的演示数据。
- 同名异币：先选候选品种，再计算行情。
- 价格口径不同：展示佣金和手续费说明，不盲目合并。
- 重复记录：后续通过平台、链接、标题、时间和编号去重。
- 原链接失效：记录发现时间和失效状态，不伪造可访问性。
- 法律与平台规则：真实接入前逐个平台评估，不绕过登录或技术限制。
