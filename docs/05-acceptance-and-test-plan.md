# 验收与测试标准

## 1. 核心任务

### 任务 A：关键词搜索

用户输入“熊猫”，能看到多个相关候选币种，并能继续缩小到某一具体品种。

### 任务 B：多关键词搜索

用户输入“2020 熊猫 30克”，相关品种应排在宽泛结果之前。

### 任务 C：俗称搜索

用户输入“袁大头 三年”，能找到对应类别和相关版别候选。

### 任务 D：盒编号查询

用户输入预设评级盒编号，只展示这枚具体币的确认记录；没有记录时明确说明暂未收录。

### 任务 E：查看市场记录

用户可以区分历史成交、当前在售和正在拍卖，并看到平台、价格、时间及原链接位置。

### 任务 F：图片识别盒号

用户上传评级盒正面照片后，页面应识别并展示候选盒号；用户可以逐位修改，只有点击确认后才会发起查询。识别失败时不得生成猜测编号。

## 2. 功能验收

- 空输入不会发起无意义搜索。
- 搜索不区分英文字母大小写。
- 多余空格不影响搜索。
- 每条演示记录均有演示标识。
- 行情统计不包含“可能相关”记录。
- 筛选和清除筛选行为一致。
- 收藏按钮有已收藏和未收藏两种状态。
- 非图片文件和超过 12MB 的图片不会进入识别流程。
- 识别结果显示可信度，并始终提醒用户逐位核对。
- NGC `8616098-030` 和 PCGS 八位纯数字编号可以进入盒号查询。

### 阶段 3 筛选与防混价

- 平台、时间、品相和价格筛选可以组合使用。
- 页面持续显示筛选后记录数，并可一键重置。
- 没有结果时显示清除筛选操作。
- 每条记录显示“确认匹配”或“可能相关”。
- “可能相关”记录不进入最近成交价、价格区间和确认记录数量。
- 每个价格均显示佣金、手续费或运费口径；未知时明确写“未知”。

## 3. 展示验收

- 常见电脑和手机宽度下内容不横向溢出。
- 主要文字和按钮对比度清晰。
- 键盘可以完成搜索和主要操作。
- 加载、空结果和错误状态均有可理解的反馈。

## 4. 数据验收

- 数据来源、状态和更新时间可见。
- 每条真实成交记录必须可以打开一对一原始交易详情页。
- 只纳入来源页明确标记为成交成功或交割成功的记录。
- 不同完整商品标题与枚、卷、套、盒等计价单位不得合并统计。
- 页面找不到真实记录时必须展示“未找到”，不得用同款币或演示价替代。
- 金额币种明确，不能默认所有外国币记录均为人民币。
- 成交价是否含佣金应可说明；未知时显示“口径未确认”。
- 外部链接必须与展示的平台一致。
