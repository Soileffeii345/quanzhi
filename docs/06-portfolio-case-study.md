# 产品经理作品集记录

本文件持续积累可用于简历和面试的项目证据，项目完成后再压缩为正式案例。

## 1. 项目一句话

设计并推动一个面向钱币收藏者的盒号追溯与行情查询产品，通过评级盒图片识别、官方认证跳转和完整盒号精确匹配，降低用户核验单枚评级币历史流转的成本。

## 2. 项目背景

钱币成交和在售信息分散在多个拍卖、收藏及二手交易平台。用户可能只知道俗称或部分关键词，同时不同年份、材质、版别和评级的价格差异明显，直接混合会产生错误判断。

## 3. 当前个人职责

- 梳理用户需求并定义 MVP 范围。
- 设计关键词搜索、候选品种和编号查询流程。
- 规划数据来源分级及风险边界。
- 制定分阶段路线图、设计规范与验收标准。
- 组织样品开发、测试和迭代记录。

## 4. 关键产品决策

- 宽泛关键词先展示候选币种，避免不同币种价格直接混算。
- 盒编号被定义为“单枚钱币追溯”，与品种行情搜索分离。
- 第一版优先验证交互价值，不把无法稳定取得的数据包装成真实能力。
- 采用小版本推进，每阶段有独立验收标准。
- 根据用户反馈将核心任务从宽泛的“多平台查价”收敛为“单枚评级盒号追溯”，重新调整首页信息架构和验收优先级。

## 4.1 已完成里程碑

- 阶段 0：建立 PRD、路线图、数据风险、设计及验收体系。
- 阶段 1：完成可交互骨架，打通关键词候选、品种详情、市场记录和盒编号追溯两条核心路径。
- 阶段 2：建立关键词标准化、别名映射、命中排序和评级编号意图识别规则，并沉淀 10 组验收测试词。
- 阶段 3：建立平台、时间、品相和价格组合筛选，并以匹配状态和价格口径阻止可疑记录进入行情统计。
- 平台接入准备：完成10个平台的统一入口和可行性分级，使“已接入数据”与“仅提供跳转”在产品上可辨识。
- 接入邮宝“交割成功”公开记录，并保留原始交易页、抓取时间和计价单位。
- 删除盒号模拟成交价；精确成交必须包含相同完整盒号，没有记录时保持空状态。
- 完成 NGC、PCGS 官方详情跳转、OCR 盒号识别及桌面/移动端验收。
