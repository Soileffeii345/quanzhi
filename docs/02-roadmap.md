# 版本路线图

项目采用“小步开发、逐段验收”的方式。每个阶段仅在前一阶段通过后开始。

## 阶段 0：项目准备（当前阶段）

目标：建立可持续的产品和开发记录体系。

- 建立 PRD、技术方案、设计规范和测试标准。
- 建立开发日志、待办和决策记录。
- 明确第一版范围与风险边界。

完成标准：文档结构完整，后续工作有明确入口。

## 阶段 1：低保真交互骨架

目标：先验证信息结构，不连接真实平台。

- 首页搜索框和搜索示例。
- 搜索结果候选币种。
- 钱币详情中的行情、历史成交、在售/拍卖区域。
- 盒编号精确查询状态。
- 手机与电脑基础适配。

完成标准：使用演示数据可走通两个核心任务。

## 阶段 2：搜索体验

目标：验证“不输入完整名称也能搜到”。

- 中文关键词的包含匹配。
- 多关键词组合匹配。
- 俗称与别名映射。
- 宽泛搜索的候选排序。
- 盒编号格式识别与精确匹配。
- 空结果、错误输入和相似结果提示。

完成标准：预设测试词均得到符合预期的结果。

## 阶段 3：结果比较与筛选

目标：让用户快速判断价格，不产生混价误导。

- 历史成交与当前市场分区。
- 平台、时间、价格、评级筛选。
- 行情统计只使用确认匹配的数据。
- 演示数据、可能相关和价格口径标识。

完成标准：用户可以解释价格来自哪些记录。

## 阶段 4：个人功能样品

目标：演示留存能力。

- 演示登录状态。
- 本机收藏。
- 本机搜索历史。
- 清除与取消收藏。

完成标准：刷新页面后，本机演示状态仍可保留。

## 阶段 5：数据可行性验证

目标：不承诺全网采集，先验证候选平台。

- 为每个平台记录公开入口、字段、更新能力与限制。
- 选取 2 至 3 个可合法、稳定使用的来源做验证。
- 形成真实数据接入建议与不可行项清单。

完成标准：给出有证据的数据来源分级结论。

## 阶段 6：作品集整理与演示发布

目标：形成可以写进简历、用于面试讲解的案例。

- 整理问题、洞察、取舍、方案、验证和结果。
- 准备演示脚本与产品截图。
- 记录个人职责和量化结果。
- 构建、验收并发布私有或受控演示地址。

完成标准：陌生面试官能在 3 分钟内理解项目价值和个人贡献。
